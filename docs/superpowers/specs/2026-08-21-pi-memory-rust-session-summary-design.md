# pi-memory-rust 退出时总结确认设计文档

- 作者：jackice
- 日期：2026-08-21
- 状态：已确认
- 关联仓库：`pi-memory-rust`
- 目的：让用户决定是否在会话结束时执行 LLM consolidate，避免默认总结拖慢 Pi 退出

---

## 1. 背景

当前 `session_shutdown` 会默认执行 LLM consolidate：

1. 收集当前 session 的 working 内容
2. 调用 LLM 生成总结/归纳
3. 写入 episodic memory
4. 再关闭 Rust 子进程

这会导致两个问题：

- **退出变慢**：LLM 调用可能耗时、失败或卡住
- **行为过于默认化**：总结是质量增强，不应强制每次退出都执行

本设计的目标是把“是否总结当前 session”交给用户选择，同时保证：

- Pi 退出不被阻塞
- 不选择总结时可以立即结束
- 非交互场景不弹窗、不等待

---

## 2. 目标

### 2.1 用户目标

用户在结束 session 时，可以选择：

- **总结并整理当前 session**
- **不总结，直接结束**

### 2.2 系统目标

- 不让 LLM consolidate 成为退出路径的默认阻塞步骤
- 不因询问用户而显著拖慢关闭
- 在用户选择总结时，仍要有超时和降级

---

## 3. 范围

### 纳入范围

- `session_shutdown` 的交互策略
- LLM consolidate 的触发条件
- 默认值与超时策略
- 退出路径的降级行为
- 相关测试与文档同步

### 不纳入范围

- 召回算法重写
- 向量索引恢复机制
- 存储结构大改
- LLM provider 实现替换

---

## 4. 设计决策

### 4.1 询问范围

**推荐只在真正退出 Pi 时询问**，也就是 `session_shutdown.reason === "quit"` 时。

其余情况直接跳过总结：

- `new`
- `resume`
- `fork`
- `reload`

原因：这些场景是 session 切换，不应该频繁打断用户，也不应把“是否总结”变成切换成本。

### 4.2 默认行为

- 默认不总结
- 用户未响应时，按“不总结”处理
- 用户选择“总结”时才执行 LLM consolidate

### 4.3 退出保障

- 询问 UI 必须有超时
- LLM consolidate 必须有硬超时
- 任何失败都不能阻塞退出
- 退出流程必须最终进入 `client.shutdown()`

### 4.4 非交互场景

在以下场景中不询问：

- `ctx.hasUI === false`
- print / JSON / RPC 无 UI 场景
- 脚本化运行

此时默认直接不总结。

---

## 5. 交互流程

### 5.1 退出流程

1. `session_shutdown` 触发
2. 判断是否为 `quit`
3. 若是 `quit` 且有 UI：
   - 弹出确认框：是否总结当前 session
   - 用户确认后执行 LLM consolidate
   - 用户取消或超时则跳过
4. 无论结果如何，最终都执行关闭清理

### 5.2 确认框文案

建议文案：

- 标题：`结束前是否总结当前 session？`
- 正文：`总结会整理当前 session 的 working 记忆，可能需要一些时间。`
- 默认：`不总结`

---

## 6. 技术实现边界

### TS 侧

- `ts/index.ts` 负责：
  - 判断 `reason`
  - 发起确认框
  - 控制是否执行 consolidate
  - 执行后端 RPC
  - 控制超时与降级

### Rust 侧

- 保持现有 consolidate/retain/store 逻辑
- 仅接收是否执行总结的结果，不负责 UI 询问

---

## 7. 错误与降级

### 7.1 用户未响应

- 视为取消总结
- 直接结束

### 7.2 LLM 超时或失败

- 记录警告
- 走规则路径或跳过
- 不阻塞关闭

### 7.3 询问 UI 不可用

- 直接跳过总结
- 不抛出影响关闭的错误

---

## 8. 测试要求

### 必须新增的测试

- `session_shutdown` 在 `quit` 时会询问用户
- 用户选择“不总结”时不调用 LLM consolidate
- 用户选择“总结”时调用 consolidate
- 非 `quit` 场景不询问
- 询问/LLM 超时不阻塞退出

### 建议验证命令

- `bun test ts/test/`
- 必要时补充针对 `ts/index.ts` 的单元测试

---

## 9. 验收标准

1. 退出 Pi 时，用户可选择是否总结当前 session
2. 选择“不总结”后，Pi 能快速关闭
3. 选择“总结”时，系统会执行 consolidate，但不会无限等待
4. 非退出场景不频繁弹窗
5. 测试覆盖关键分支
